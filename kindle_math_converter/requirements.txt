# The document parser. This is the pipeline's front half — it replaced the old
# YOLO + PaddleOCR + pix2tex stack entirely, so none of those appear here.
#
# THE PLATFORM EXTRA IS NOT OPTIONAL — it IS the GPU backend. Without it
# MinerU silently falls back to `transformers` on CPU, which is not a slower
# version of the same thing: it is slow enough (tens of hours for a textbook)
# to be unusable. See the README, "System requirements".
#
#   `vlm`   the VLM backend itself (torch, transformers, accelerate)
#   `mlx`   Apple Silicon GPU, via Metal
#   `vllm`  NVIDIA CUDA GPU
#
# Deliberately NOT `core`, which is `vlm` + `pipeline` + `gradio`: `gradio` is a
# web UI this project never launches, and `pipeline` is MinerU's non-VLM backend
# (OmniDocBench 86.47 vs the VLM path's 95.30) which this project rejects on
# accuracy. Together they are ~25 unused packages including a second copy of the
# torchvision/onnxruntime stack.
#
# Pinned: MinerU's version determines the recognition output, and an unpinned
# upgrade changes equations in a way nothing downstream will flag.
#
# LINUX USERS: pip cannot resolve the `vllm` branch of this tree — it backtracks
# through cffi sdists indefinitely (observed >10 min with no end). Use uv, which
# resolves it in about five seconds:
#
#   uv pip install -r kindle_math_converter/requirements.txt
#
# A known-good fully-pinned Linux x86_64 set already exists in the repo root as
# modal-requirements.txt (`uv pip compile` of `mineru[core,vlm,vllm]==3.4.4`).
# It is what the Modal GPU image is built from, so it is the most-tested Linux
# dependency set here — prefer it if you are standing up a Linux box.
#
# macOS needs none of this: the mlx branch resolves under plain pip in seconds.
mineru[vlm,mlx]==3.4.4 ; sys_platform == "darwin"
mineru[vlm,vllm]==3.4.4 ; sys_platform == "linux"
